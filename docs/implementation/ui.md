# Egoist 3.2.0 RC — интерфейс и брендинг

Версия результата: **ui-rc-01**, приложение **3.2.0-rc.1**, исходная точка `d315ba1` / 3.1.10. Дата проверки: 6 октября 2026. Изменения реализованы в существующем приложении и работают через его IPC; демонстрационные fixtures существуют только в тестах.

## Что изменилось

| Исходная проблема | Результат | Проверка |
| --- | --- | --- |
| Основной экран и дополнительные списки требовали нескольких переходов для сравнения аккаунтов | Стартовый раздел «Профили», native таблица «Профиль / Остаток / Свежесть / Состояние / Действия», поиск, фильтр всех провайдеров, сортировки; карточки сохранены | 1/10/100/200 профилей; compiled Electron и браузерные DOM-сценарии |
| Выбранный профиль и фактический аккаунт IDE обозначались одним состоянием | «Выбран» отдельно от runtime evidence; четыре уровня проверки и сообщение «Аккаунт работающей IDE не подтверждён» | Отдельный probe B не превращает Desktop в подтверждённый B; ручное повторное применение доступно |
| Нулевые, неизвестные и дробные лимиты могли выглядеть одинаково | Общий quota/readiness view model; неизвестное «—», положительный остаток меньше 1% — «<1%»; фактические периоды и все buckets в inspector | Дробные остатки, неизвестные квоты, произвольное двухчасовое окно, model/scope, stale/reset/error |
| Импорт применялся без видимого предварительного результата | `previewImport → applyImport`, количества новых/пропущенных записей, список конфликтов с пропуском по умолчанию | Apply не вызывается до отдельного действия в предварительном результате |
| Скрытие входа выглядело отменой | Pending попытка сохраняется и открывается кнопкой «Продолжить вход»; secret inputs очищаются при скрытии и отправке | Возврат к тому же loginId без второго startLogin |
| Недоступные действия строки и непредсказуемый фокус | Arrow/Home/End выбирают строку, Enter открывает подробности; переключение требует кнопки; общий inspector и модальный focus manager | Фокус после обновления списка, вложенный confirm, Tab/ShiftTab/Escape, возврат к открывшей кнопке |
| Ручной откат выглядел универсальным действием над историей | Журнал предлагает восстановление только последнего подходящего snapshot; подтверждение показывает дату и закрытие IDE | Текущий matching snapshot, блокировка старого snapshot после нового rollback, provider recovery; backend остаётся авторитетом |
| Неполный перевод, радиоэлементы без клавиатуры, email/path в атрибутах | RU/EN основных поверхностей, radio roving tabindex и стрелки; privacy маскирует текст и DOM-атрибуты | Таблица, карточки, inspector, обзор, настройки, команды, login/import, tray и hover |
| Несколько больших CSS-слоёв переопределяли друг друга | Один основной `styles.css`; старые v3/v306–v310 слои удалены; компактный responsive layout от 860×560 | Геометрия на 860×560, 1080×780, 1460×900; sticky header; доступность последней строки |
| Таймеры и IPC-перечитывания повторялись по поверхностям | Один visible clock, остановка при скрытии, deduplicated tray reload, сохранение snapshot при ошибке refresh; необязательная диагностика после оболочки | Старение свежести без network refresh; hidden clock=0; ошибка tray сохраняет данные |

GodMode и подмена fingerprint удалены из обычных настроек. Локальное обнаружение профиля обозначается как обнаружение, а не подтверждение входа. Для явного переноса Antigravity secrets сохранены подтверждения через общий диалог.

Основная навигация: **Профили / Обзор / Журнал / Настройки**. Новые действия интегрированы с backend API, существующие технические storage identifiers не менялись этим потоком работ.

## Визуальная система

Видимое название — **Egoist**, без AI. Собственный компактный знак E состоит из трёх срезанных полос с фиолетовой средней полосой; исходники и экспорт находятся в [assets/brand](../../assets/brand/README.md). Имя уже применяется сторонним программным продуктом: оригинальность графики не является подтверждением уникальности товарного знака.

Чёрно-белая основа, фиолетовый акцент, красный для ошибок и критичного остатка. Полосы лимитов — 7px, включая tray и пассивную подсказку. Unbounded используется в заголовках и метриках, Montserrat с кириллицей — в основном тексте; OFL-лицензии сохранены рядом с branding assets. Переходы состояния короткие; `prefers-reduced-motion` отключает анимацию.

Рассчитанные контрасты непрозрачных пар: белый / #050507 **20.36:1**, #b7b0c4 / #050507 **9.72:1**, #c084fc / #050507 **7.71:1**, белый / #7c3aed **5.70:1**. Это проверка конкретных пар, не сертификация всего приложения по WCAG.

Размер icon.png уменьшился с 170098 до **9684 bytes**, icon.ico — с 95947 до **13599 bytes**. PNG и ICO имеют локальный редактируемый источник; генерация не загружает внешний логотип.

## Проверки и воспроизводимость

Типы и ESLint проходят. UI unit tests: **3 файла / 13 тестов**. Финальный canonical `pnpm smoke` с pnpm **11.28.0**: **43 PASS / 1 SKIP / 0 FAIL**, exit **0**, 44 сценария за 2.4 минуты. Группы: **26 основных browser DOM + 9 browser DPI emulation + 8 compiled Electron PASS**; один exact-package main-inspection сценарий пропущен из-за production fuses. Источники, dist, raw log и ограничения зафиксированы в [UI verification receipt](../receipts/ui-verification-3.2.0-rc.1.json).

Compiled Electron UI: **8/8 PASS**, плюс один неприменимый exact-package main-inspection сценарий. В этой группе использовались реальные compiled `dist/main`, SQLite с Electron ABI145 и compiled renderer, запущенные development Electron 41.10.7. Проверены 1/10/100/200 синтетических профилей, каждый на 860×560 / 1080×780 / 1460×900, Home/End/Enter/Escape, RU/EN, privacy, IPC-настройки, onboarding и hidden startup. Secret material — безвредный placeholder; операции переключения, входа и provider probes не запускались.

Каждая native попытка получает собственный UUID root, `.egoist-probe-root.json` marker, отдельные userData/CODEX_HOME/HOME/USERPROFILE/APPDATA/LOCALAPPDATA. Native adapters запрещают host Credential Manager, автозапуск, внешние IDE и сеть провайдеров. Удаляется только проверенный root данной попытки. Браузерные fixtures блокируют внешние запросы и не добавляются в shipping code.

Старые v309/v310/ui-preview сценарии заменены актуальными проверками. Их полезные требования сохранены: геометрия обзора, официальные способы входа, отсутствие privileged effects, unknown quotas, достижимость профилей/настроек/аудита, privacy. Старые source-string/CSS-string unit assertions заменены view-model и DOM-проверками поведения.

Воспроизведение после сборки с Electron ABI:

```powershell
# CAM_TEST_WORK_DIR — отдельная временная папка текущей задачи.
pnpm smoke
# Отдельно development browser fixtures:
pnpm exec playwright test --config tests/smoke/renderer.config.ts
# Отдельно compiled Electron с изолированными данными:
pnpm exec playwright test --config tests/smoke/native.config.ts
```

Canonical suite содержит отдельные browser и compiled Electron группы сценариев и выполняет каждый spec один раз. На локальном Windows используется установленный Edge, в CI — установленный Chromium; browser channel можно указать через `CAM_PLAYWRIGHT_CHANNEL`. Node-native unit tests выполняются в своей ABI-группе до Electron rebuild.

- [Inspector и четыре уровня подтверждения](../images/3.2.0-rc.1/native-inspector-1460x900.png).

Снимки пересняты в финальном canonical smoke после последнего CSS-исправления tray подсказки. Использован актуальный compiled `dist`; эта группа отличается от проверки неизменённого shipping EXE.

Браузерный `deviceScaleFactor` 1/1.5/2 проверяет эмуляцию масштаба, не реальные Windows DPI 100/150/200%. Windows DPI не менялся, сравнение в VM не выполнялось. Development Electron с compiled приложением не подменяет проверку точного неизменённого shipping EXE: production fuses запрещают main inspection; startup/package проверяет root отдельными средствами без ослабления fuses.

Не проверялись реальные аккаунты IDE, live OAuth, перезапуск пользовательских IDE, screen reader, soak, точные показатели CPU/RAM и сравнение конкурентов. Они не выдаются за результаты этих UI-проверок. Snapshot identity подтверждается только backend evidence; локальная готовность credentials и независимый probe не доказывают Desktop identity.

## Обратная связь

Предметы companion review board итогового отчёта: таблица и inspector; раздельные уровни подтверждения; Egoist identity; доступность/приватность/перевод. Версия каждого предмета **ui-rc-01**; подтверждение означает принятие показанного результата, а не запуск входа, отката или операций с реальными IDE. Ответы пользователя и точный snapshot сохраняет корневой итоговый review board проекта.
