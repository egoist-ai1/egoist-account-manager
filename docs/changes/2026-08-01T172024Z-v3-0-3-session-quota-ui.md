# Version 3.0.3 session, quota and UI hardening

- Date: `2026-08-01T17:20:24Z`
- Type: `release`
- Status: `complete`
- Related: `docs/product-3.0-spec-2026-07-29.md`, T15

## What changed

- Added bounded local snapshots of recognized active Codex credential rotation into the DPAPI vault at startup, every 30 seconds, on blur/suspend/lock and before quit.
- Split credential health from quota transport health, preserving the last successful quota snapshot while recording a separate transient error and exponential backoff.
- Made app update checks/downloads explicit, bounded and progress-aware; prevented overlapping implicit/explicit operations.
- Reworked Overview, account cards and Settings around a compact 1200×700 shell with progressive disclosure and separate credential/quota states.
- Removed an unintended 460 ms animation delay that briefly rendered the Accounts workbench fully transparent.
- Bumped product/release metadata to 3.0.3 and generated exact installer, portable, update metadata and SHA-256 manifest.

## Why

Managed accounts needed to survive Manager and Windows restarts without repeatedly restoring stale rotated credentials. Quota transport failures also needed to stop masquerading as lost authorization, while the interface needed a faster and less crowded operating surface.

## How

Session capture is local and identity-gated: only one unambiguous fingerprint, provider/workspace or JWT-email match may update an encrypted vault. It never starts the app-server or changes the Codex process lifecycle. Quota persistence uses DB migration v9 and keeps refresh errors separate from successful data. Switch behavior continues to use the existing journaled exact-lifecycle/rollback transaction.
