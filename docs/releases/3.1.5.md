# Codex Account Manager 3.1.5

- [User-facing release notes](../../RELEASE_NOTES_3.1.5.md)
- Stage: public stable; guarded GitHub publication and public 5/5 asset verification passed.
- SHA-256 manifest: `release/SHA256SUMS-3.1.5.txt`.

## Root cause and correction

The production log reproduced `prepare → target reauth still pending → accounts:switch rejection`. The prepared singleton transaction remained non-terminal, so every later prepare failed with `Another switch transaction is already active` until Manager restarted.

3.1.5 rejects target reauth before creating a transaction, fails a transaction if reauth starts after prepare, terminates prepared work when the cross-process lock rejects, and supersedes duplicate reauth sessions for the same profile. A successful commit updates the active card immediately; the follow-up reload is non-blocking.
